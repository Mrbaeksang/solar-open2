# AI를 책임 있게 사용하기

<Lead>
책임 있는 AI 사용은 개인의 “주의”만으로 해결되지 않습니다. 데이터를 수집한 조직, 모델 제공자, 서비스를 도입한 기관, 결과를 승인한 담당자, 영향을 받는 사람이 서로 다른 정보와 권한을 가집니다. 위험과 책임을 이 행위자 사이에 구체적으로 배치해야 합니다.
</Lead>

<LessonSection id="rights-data" title="권리와 데이터 처리">

AI 서비스에 정보를 넣는 순간 입력이 어디로 전송되고 얼마나 보관되는지 질문해야 합니다. 서비스 제공에 꼭 필요한가, 다른 목적으로 재사용되는가, 삭제와 열람이 가능한가를 확인합니다. 미성년자, 건강, 생체, 위치 정보는 특히 큰 피해를 만들 수 있습니다.

AI에 데이터를 입력하거나 결과를 재사용할 때는 수집 목적, 동의, 최소 수집, 보관 기간, 저작권과 이의제기 수단을 확인해야 합니다. <Cite claim="s07-rights" />

생성 결과의 저작권 상태도 “AI가 만들었으니 자유”라는 한 문장으로 정리되지 않습니다. 학습 자료, 프롬프트에 넣은 원문, 출력의 실질적 유사성, 관할 법과 계약 조건이 관련됩니다. 교육 과제에서는 허용된 도움 범위와 표시 규칙을 먼저 확인합니다. 개인정보나 저작물을 처리하지 않는 대안, 로컬 처리, 최소한의 발췌를 우선 검토합니다.

<TryIt title="데이터 흐름표">
회의록 요약 AI를 도입한다고 가정하고 수집, 전송, 처리, 보관, 삭제 단계마다 데이터 주체와 책임자를 표시하세요. 꼭 필요하지 않은 필드를 지웁니다.
</TryIt>

</LessonSection>

<LessonSection id="bias-accountability" title="편향과 책임의 귀속">

모델 출력이 차별적일 때 “데이터가 그랬다”는 설명은 원인을 일부 말할 뿐 책임을 끝내지 않습니다. 어떤 자료와 목표를 승인했는지, 집단별 오류를 측정했는지, 불리한 결정을 뒤집을 절차가 있는지를 봐야 합니다.

AI 출력은 책임 주체가 될 수 없으므로 설계·도입·운영·결정 권한을 가진 사람이 영향과 구제 절차에 책임져야 합니다. <Cite claim="s07-accountability" />

채용 모델 제공자는 기술 한계와 평가 자료를 공개할 책임이 있고, 도입 조직은 직무 타당성과 차별 영향을 검토할 책임이 있습니다. 담당자는 추천을 비판적으로 읽어야 하지만 충분한 정보와 권한을 받지 못했다면 모든 책임을 개인에게 떠넘길 수 없습니다. 영향을 받은 지원자에게 설명과 이의제기 경로를 제공해야 합니다.

<Boundary>
공정성은 모델 지표만의 성질이 아닙니다. 목표가 부당하거나 구제 절차가 없다면 집단별 오류율을 맞춘 모델도 책임 있는 시스템이 아닐 수 있습니다.
</Boundary>

</LessonSection>

<LessonSection id="meaningful-oversight" title="형식이 아닌 실질적 인간 감독">

“최종 결정은 사람이 한다”는 문구는 자주 안전장치로 제시됩니다. 그러나 담당자가 하루에 수천 건을 처리하고 모델 근거를 볼 수 없으며 거부하면 불이익을 받는다면 승인 버튼은 고무도장에 가깝습니다.

실질적 인간 감독에는 결과를 이해할 정보, 검토할 시간, 결정을 거부·수정할 권한과 책임, 이의제기 경로가 필요합니다. <Cite claim="s07-oversight" />

고위험 사용에서는 AI를 쓰지 않는 선택도 검토해야 합니다. 의료 진단, 형사 사법, 복지 자격처럼 오류가 생명과 권리에 큰 영향을 미치면 사전 영향평가, 분야 전문가 검토, 지속 모니터링과 중단 기준이 필요합니다. 효율 향상이 권리 침해를 정당화하지 않습니다. 시스템을 누가 멈출 수 있는지가 책임 구조의 실제 시험입니다.

<TryIt title="감독 설계">
학교의 AI 부정행위 탐지 결과를 교사가 검토합니다. 교사에게 필요한 정보·시간·권한, 학생의 이의제기 절차, 시스템 중단 기준을 각각 적으세요.
</TryIt>

</LessonSection>
